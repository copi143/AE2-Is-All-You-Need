# EMI 分类数据采集

进入目标整合包的世界或服务器，等待 EMI 的索引和配方加载完成，在聊天栏执行客户端命令：

```text
/ae2inya dump-emi-classification
```

Forge 和 Fabric 均支持，无需服务器安装该命令或授予作弊权限。命令仅在 EMI 存在时注册。
采集游戏数据在客户端主线程执行，大型整合包可能短暂停顿；JSON 写入在后台进行。
完成后聊天栏和客户端日志会显示绝对路径：

```text
<游戏目录>/.tmp/emi-classification/items-<随机编号>.json
```

开发环境通常位于 `forge/run/.tmp/emi-classification/` 或 `fabric/run/.tmp/emi-classification/`。
每次导出保留独立样本。分析完成后可删除不再需要的文件。

## 数据内容（schemaVersion = 1）

| 字段 | 内容与用途 |
| --- | --- |
| `items` | 完整物品注册表，包含未进入 EMI 的物品；注册 ID、翻译键、默认堆栈、物品类、关联方块信息 |
| `emiStacks` | 未经过折叠和搜索过滤的 EMI 索引，保留索引顺序、同 ID 的 NBT 变体、流体和自定义资源 |
| `classes` | 类名对应的完整父类链与接口集合，用于比较“精确类”与“语义父类”分组 |
| `creativeTabs` | 当前功能开关和玩家权限下的创造模式分类与成员，包含成员 NBT；不包含搜索/快捷栏/背包等特殊页 |
| `recipeCategories` | 配方类别 ID、名称与工作站；索引成员另有作为输入/输出时的类别计数 |
| `legacyCandidateKeys` | 旧规则为索引成员生成的候选键，不代表经过门槛和优先级判断后的实际归属 |

物品堆栈包含当前同步的标签、显示名、普通/高级 Tooltip、NBT（SNBT 字符串）、堆叠上限、耐久、附魔、食物标志、稀有度、使用动作及合成余物。额外采集各装备槽的属性修饰、`TieredItem` 工具等级/速度/伤害、`ArmorItem` 护甲槽位/材质/防御，用于判断不同材质是否属于同一功能家族。方块额外包含标签、类、状态属性及其可选值、默认状态、方块实体标志。非物品 EMI 资源另有 key 类、序列化表示、NBT、Tooltip，流体还有流体标签。

顶层记录时间、Minecraft 版本、加载器、开发/生产环境、语言、权限和数量统计。
单字段采集失败记入所在对象的 `errors` 并累计 `errorCount`；缺失字段伴随错误不能当作“没有该特征”。
EMI 未就绪时拒绝导出，采集中检测到 EMI 重载则要求重试。

## 如何据此重构

先对目标整合包样本分析标签覆盖率、类层次分布、ID 家族、创造栏归属、NBT 变体与配方角色，再选择分类依据：

1. 优先评估有明确语义的标签和父类/接口，区分材料形态、工具、护甲、容器、机器等。
2. 用 ID 与翻译键识别材质、容量、档位等家族内变化；注册命名空间用于区分模组特有语义。
3. 创造栏和配方类别作为辅助证据，评估其过宽或多义情况；显示名和 Tooltip 主要用于人工解释，避免规则依赖游戏语言。
4. 显式区分物品、流体及自定义资源；保留 NBT 变体，检查同 ID 不同用途是否应分开。
5. 用完整索引建立稳定分组，搜索只裁剪可见成员；统一侧边栏和收藏恢复的成员解析，给每组保留分类理由。

这些是数据分析方向，尚未替换现有规则。最终规则和阈值需要实际运行样本；仅凭源码无法知道目标整合包同步后的标签、插件注册的 EMI 变体与配方。
